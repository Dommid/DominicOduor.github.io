04 / DETECTION & ANALYTICAL REASONING

Logs are useful.
Context makes them actionable.

The monitoring report's final written memo identified event ingestion as useful while calling out missing contextual fields and correlation limitations.

OBSERVED IN LAB REPORT

What the exercise documented

  • pfSense firewall events and Snort alerts were examined.
  • Snort detection was exercised on separate monitored interfaces.
  • Splunk indexed detection events during controlled activity.
  • The analysis noted that event records alone did not always clarify the full simulated activity path.
PROPOSED IMPROVEMENTS

Recommendations from the analysis

  • Include source and destination hostnames and richer asset context.
  • Use clear rule names and standardized event timestamps.
  • Correlate authentication attempts, related alerts, and affected assets.
  • Develop focused DMZ dashboards and automated monitoring alerts.
Verification boundary: These are exercise observations and recommendations, not proof that new Splunk dashboards, enrichment pipelines, or correlation rules were implemented or independently measured after the lab.

05 / DEFENSIVE RECOMMENDATIONS

Reduce unnecessary exposure.
Improve detection confidence.

01 / SEGMENTATION

Constrain DMZ-to-LAN paths

Allow only explicitly required traffic across security zones, limiting opportunities for lateral access from exposed services.

02 / SERVICE HYGIENE

Minimize external services

Disable unnecessary or insecure protocols, apply updates, and prefer encrypted management and application access.

03 / LOG QUALITY

Connect telemetry to assets

Improve host attribution, timestamp consistency, alert context, and SIEM correlation for faster investigations.

Recruiter takeaway

These labs demonstrate hands-on firewall policy configuration, IDS alert review, central logging, network vulnerability assessment, and risk-informed defensive recommendations—within clearly identified educational environments.
