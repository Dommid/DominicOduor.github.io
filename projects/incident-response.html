02 / RESPONSE WORKFLOW

From an observation
to a response plan.

The stages below reflect the lab's documented task sequence. They represent an educational workflow, not independently validated attack reconstruction.

  1. Review security telemetry

    Inspect monitored log sources and file integrity monitoring configurations for web content and relevant system activity.

  2. Identify and scope the reported issue

    Review a suspicious-content scenario and use logged evidence to investigate the affected web environment and possible origin.

  3. Correlate events and investigate access

    Review logged activity, including an SSH full_log event and key fingerprint information, to support analysis of potentially compromised access.

  4. Document containment and root-cause tasks

    Track the exercise's containment, investigation, and root-cause checkpoints; distinguish evidence from a hypothesis or an intended response.

  5. Plan remediation and recovery

    Document remediation and server-restoration tasks, including an SSH key revocation procedure and configuration-monitoring improvements.

05 / PREVENTION & REMEDIATION

Security lessons
with operational value.

01 / VISIBILITY

Monitor critical changes

Review file integrity coverage and security telemetry on configuration files and application content to improve event visibility.

02 / ACCESS

Revoke compromised trust

For suspected SSH key compromise, document affected accounts, remove or revoke unauthorized keys, and validate access changes in the authorized lab.

03 / RECOVERY

Track closure evidence

Associate remediation and restoration tasks with verification evidence before calling an incident resolved.

Recruiter takeaway

This lab demonstrates a structured approach to reviewing telemetry, investigating suspicious activity, documenting an incident, and selecting security controls. It is presented as hands-on academic experience, not professional production incident-response ownership.
